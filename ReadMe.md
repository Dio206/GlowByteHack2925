# Прогноз самовозгорания угля (GlowByte Hack)

Проект представляет собой **интегрированное решение для прогнозирования риска самовозгорания угля на открытых складах**. Система помогает предприятиям минимизировать риск пожаров, финансовых потерь и угрозу жизни сотрудников.

---

## Цель проекта

Создать **надёжный инструмент для предотвращения пожаров на складах угля**, который сочетает машинное обучение, быстрый API и удобный фронтенд для бизнес-пользователей.

---

## Описание  функционала 
1. Загрузка данных и запуск прогнозирования

   -  Эндпоинт: POST /predict_data
      - Пользователь загружает три файла:
      погодные данные,
      данные о поставках угля (когда штабель был сформирован и когда отправлен),
      данные о замерах температуры внутри штабелей.

      - Что делает приложение:
      Объединяет все данные в единую таблицу на каждый день.
      Создаёт признаки (возраст угля, скорость нагрева, скользящие средние, метeoфакторы и др.).
      Генерирует координаты штабелей.
      Запускает прогноз модели.
      Сохраняет все вычисленные данные в кэше.
      Возвращает только дни с риском > 0.60.

      - Эти данные используются в интерфейсе для:
      подсветки календаря,
      списка рисковых дней,
      отображения карты,
      карточек штабелей.
2. Календарь с подсветкой дней риска (красный цвет)

   - Эндпоинт: GET /risk_calendar_dates

      - Функционал:
      Выдаёт список всех дат, когда вероятность риска превышала 0.60.
      Для каждого штабеля возвращается массив дат.
      Интерфейс подсвечивает такие даты красным, предупреждая персонал.

3. Детальная информация по штабелю на конкретную дату

   - Эндпоинт: GET /stack_details/{stack_id}/{date}

      - Возвращает:
      вероятность риска,
      статус («норма» или «в зоне высокого риска»),
      температуру,
      скорость нагрева (RoR),
      возраст угля,
      тип угля,
      координаты X/Y(для карты)

      Это используется для карточки, которая открывается по клику на календарь или на карту.

4. Список всех штабелей с агрегированной статистикой

   - Эндпоинт: GET /list_all_cards

      - Приложение:
      собирает по каждому штабелю максимум риска,
      считает количество ризковых дней,
      считает общее количество дней существования штабеля,
      возвращает данные в удобном формате для карточек.

      - Использование:
      отображение панели «все штабели»,
      сортировка по уровню риска,
      построение тепловой карты склада.

5. Расчёт метрик точности модели

   - Эндпоинт: POST /calculate_metrics

   Принимает файл фактических пожаров.

      - Приложение считает:
      Recall,
      Precision,
      F1-score,
      AUC-ROC,
      accuracy,
      количество реальных рисковых дней,
      temporal accuracy — доля пожаров, предсказанных заранее (за 1–3 дня).

      - Использование:
      контроль качества модели,
      отчёты,
      сравнение со следующими версиями.

6. Вспомогательные функции

- load_data_from_files(...)
   - Основная функция предобработки:
   создаёт ежедневные записи для каждого штабеля,
   присваивает координаты,
   объединяет погоду и замеры температуры,
   генерирует признаки (возраст, скользящие средние, RoR),
   заполняет пропуски,
   кодирует категории,
   возвращает готовую таблицу.

- format_card_data(...)
   - Упаковывает данные для отображения в карточке штабеля.

- calculate_temporal_accuracy(...)
   - Считает, как часто модель успела предупредить заранее.

## Архитектура

1. **Модель прогнозирования (CatBoost)**
    - Анализирует исторические данные о самовозгорании.
    - Выдаёт вероятность риска для конкретного склада.
    - Учитывает параметры окружающей среды, влажность, температуру угля и другие факторы.

2. **API сервер (FastAPI)**
    - Получает данные от фронтенда.
    - Передаёт их модели и возвращает результаты прогнозирования в формате JSON.

3. **Фронтенд (React)**
    - Удобный интерфейс для менеджеров и сотрудников.
    - Ввод параметров склада и получение прогноза риска.
    - Визуализация прогнозов через графики и индикаторы.
    

4. **Возможности для дальнейшего развития**
    - Интеграция с системами оповещения.
    - Логи и аналитика для аудита и страховых компаний.
    - Поддержка нескольких складов и пользователей.
    - Возможность просмотра истории прогнозов и экспорта отчётов.

# Инструкция по запуску проекта

## Бэкенд

### 1. Создание виртуального окружения

```bash
   python -m venv myenv
   myenv\Scripts\activate
```

### 2. Установка зависимостей

```bash
   cd backend
   pip install -r requirements.txt
```

### 3. Запуск сервера

```bash
   cd model
   py -m uvicorn main:app --reload
```

> Сервер будет доступен по адресу: `http://127.0.0.1:8000/`


## Фронтенд

### 1. Установка зависимостей

```bash
   cd frontend
   npm install
```

### 2. Запуск приложения

```bash
   npm run dev
```

> Приложение будет доступно по адресу, указанному в терминале.


### Выбор архитектуры модели и подхода к обучению.

   - Архитектура модели: CatBoost
      -  Хорошо работает с категориальными данными
         Например, тип угля - категория. CatBoost умеет работать с ними напрямую.
         Нам не нужно вручную кодировать категориальные признаки.

   - Как мы обучали модель
      - Тип задачи: определить, есть риск самовозгорания или нет → бинарная      классификация.
      - Как мы поставили целевую переменную:
         - Если пожар был, то три дня перед ним тоже считаются «опасными».
         Это даёт время на предупреждение и реакцию.
         Почему так:
         Предупреждение в момент пожара бесполезно. Нужно предупредить заранее, чтобы успеть перелопатить, охладить и т.д.

   - Почему мы выбрали такие метрики и как их понимать
      - Задача очень важна для безопасности, поэтому нужно правильно измерять качество модели.
      Простое объяснение метрик:
         - Recall (Полнота) — самое важное
            Показывает, какую часть настоящих опасных ситуаций мы не пропустили.
         - Precision (Точность)
            Показывает, насколько часто наши предупреждения реально правильные.
         - F1-score
            Среднее между полнотой и точностью.
            Показывает общий баланс между «не пропустить пожар» и «не тревожить зря».
         - AUC-ROC
            Показывает, насколько хорошо модель вообще отличает «норму» от «риска», независимо от порога.
